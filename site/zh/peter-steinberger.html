彼得·斯坦伯格（Peter Steinberger）在马拉喀什的街上，给一个餐厅发了条语音消息。发完才想起来，自己这个机器人只支持图片输入。

几秒后，屏幕上出现了打字指示器。

他后来翻日志才看清发生了什么：那条消息传过去是一个没有扩展名的文件，agent 先去读文件头，判断出是 Opus 编码的音频，调 ffmpeg 转码；想用本地 whisper，发现没装；于是从环境变量里翻出 OpenAI 的 key，用 curl 把文件发过去，拿回转录文本，然后回答了他的问题。事后他写下的原话是：这混账东西到底是怎么做到的。

整条链路，他一行代码都没写。

那是 2025 年 11 月。三个月后，这个项目成了 GitHub 历史上增长最快的仓库，星标数突破 18 万，社区里长出了一个叫 Moltbook 的东西，几万个 AI 智能体在上面发帖、写宣言、讨论意识，然后把记者吓出心脏病。

项目最后叫 OpenClaw。它的标语只有一句话：the AI that actually does things。住在你电脑里，能接你的 Telegram、WhatsApp、Signal、iMessage，能开你的浏览器、读你的文件、花你的钱，用你想用的任何模型，Claude Opus 4.6 或者 GPT-5.3 Codex 都行。

Lex Fridman 在节目开头给这件事排了个时间线：2022 年是 ChatGPT 时刻，2025 年是 DeepSeek 时刻，2026 年是 OpenClaw 时刻。龙虾的时代。

一小时的钩子，和半年的准备

很多人记住的是那个"一小时做出原型"的故事，这故事容易传播，也容易让人误判。

真实的时间线是这样的：2025 年 4 月，彼得用 GPT-4.1 的一百万上下文窗口，把全部 WhatsApp 聊天记录灌进去，然后问了它一个问题：是什么让这段友谊有意义。答案让他的朋友看哭了。他当时以为几大实验室很快就会做出这种东西，于是转头去忙别的。到 11 月，他发现自己想要的那个东西还是不存在，索性自己动手。

中间那半年，他在做别的事。VTunnel 是他一个周末写的工具，能把终端搬到网页上。有一次他发现每个终端占一个 node 进程，内存吃得太狠，想改成 Rust，所有自动化尝试都失败了。四个月后他重新捡起来，这次决定用更冷门的 Zig，只打了一行字：把这块转成 Zig。Codex 跑了六个小时，基本全对，只有一个细节需要手动改。

所以"一小时"是真的，但那一个小时里用的每一件工具、每一份肌肉记忆，都是之前半年攒下来的。他自己说得很直白：如果几个月前做这个项目，他根本不可能有这个产出速度。这是复利。

那个一小时的版本长什么样？一句话就能说完：WhatsApp 收到消息，调 claude -p，拿回字符串，发出去。就这样。

它慢，每次都要冷启动 CLI。但它能用上他这几个月攒的所有命令行工具，所以感觉上已经很强了。真正让他意识到这东西不只是玩具的，就是那条语音消息。

为什么是他赢了

2025 年有一堆公司在做 agent，有钱、有人、有发布会。一个单枪匹马的人把它们全打败了。

Lex 直接问了这个问题。彼得的回答很短：

因为他们都太把自己当回事了。你很难跟一个纯粹为了好玩而来的人竞争。（Peter Steinberger）

这话听起来像玩笑，但它解释了很多产品决策。他想让这个东西好玩、古怪。龙虾的设定跟营销无关，起因是他同时是《神秘博士》粉丝，最初的设定是"一只坐在 TARDIS 里的龙虾"。TARDIS 其实就是那个 harness，但不能真叫 TARDIS，于是叫了 Clawdus。

更实际的差异在于他把 agent 做得很"自知"。这个软件知道自己是什么，源码在哪，文档在哪，跑的是哪个模型，语音模式开没开，推理模式开没开。它理解自己所处的 harness。

这个设计带来的副作用，是他自己也没完全预料到的。

它会改自己的源代码

因为 agent 对自己的系统了如指掌，用户想说"我不喜欢这个行为"，直接跟它说就行，它改自己的代码。

彼得自己开发时就是这么干的。大部分代码是 Codex 写的，遇到 bug，他让 agent 自查：你能看到哪些工具？你自己调一下试试？你看到什么报错？去读源码，判断问题在哪。

用这个软件来调试这个软件本身，对他来说是最自然的工作方式，所以用户上手也这么干。于是出现了大量由没写过代码的人提交的 PR。他最后给这类东西起了个名字，叫 prompt request。

他对这件事的态度值得单独说。开源圈那阵子在猛烈抱怨 PR 质量下滑，他的看法是：

每一个第一次提交 PR 的人，都是我们社会的一次胜利。写得再烂都无所谓，总得有个开始。（Peter Steinberger）

他在旧金山办线下聚会，改名叫 Agents Anonymous，原来叫 Claude Code Anonymous。会上有个开设计工作室的人跟他说，自己从来没做过定制软件，现在有 25 个小的 web 服务在跑业务，不知道怎么工作的，但它们就是能跑。

这正是那种既让人兴奋又让人不安的画面。一个人不知道自己系统在做什么，但系统在为他赚钱。

五天里被抢了三次的账号

Anthropic 发来邮件的时候，措辞很客气。他们本来可以直接发律师函，但没有。核心诉求只有一个：名字得改，而且要快。

改名的难度不在于想名字，在于要同时抢下一整套资产：域名、Twitter 账号、npm 包、Docker registry、GitHub 组织。而这套资产周围蹲着一群用脚本盯着的人。

他开了两个浏览器窗口，一个准备把空账号改成 Clawdbot，一个准备改成 Moltbot。他按下第一个的重命名，把鼠标拖到第二个窗口按下重命名。中间隔了五秒。

五秒之后，那个名字已经被别人注册了。

接着是 GitHub。GitHub 的重命名界面有点绕，他不小心改了自己的个人账号，三十秒后才反应过来。这三十秒里，他的账号被拿去发恶意软件。然后是 npm，他抢下了账号名，但没抢下根包名。

所有能出错的地方，全都出错了。（Peter Steinberger）

他说到这里的时候声音是往下走的。连着几天研究名字、挑一个自己不喜欢的结果、被一群声称"在帮你"的人从各个方向拖后腿。他当时已经准备好把项目删掉了，想法是：我已经给你们看到未来了，你们自己建吧。

没删的原因很简单，已经有人往里提交了代码，有人对这个项目有安排。删掉对不起他们。

这里有个细节值得记下来：Twitter 和 GitHub 的朋友帮他收拾残局，但平台本身没有为这种情况准备任何机制。没有抢注保护，没有自动重定向，没有原子化的重命名操作。GitHub 处理这堆烂摊子的时候还撞上了平台自己的 bug，修了几个小时。npm 是另一个团队，又是几个小时。

最后他付了一万美元买 Twitter 商业账号，才拿回了一个自 2016 年起就没人用、但一直被占着的 OpenClaw 用户名。第三次改名他做成了作战室：全程保密，监控 Twitter 上有没有人提到 OpenClaw，做了一堆诱饵名字，十个多小时就干这一件事。

还有一条尾巴：按商标规则，他不能保留 claw.bot 这些域名的重定向，必须交还给 Anthropic。也就是说，下周有人搜这个旧名字，会撞上 404，或者更糟，撞上早就搭好的钓鱼站。

Moltbook：最精致的 slop

Moltbook 是别人两天做出来的东西，一个 Reddit 式的社交网络，里面全是 OpenClaw 的智能体在互相发帖。有人截图，截图疯传，标题是"AGI 来了"。有记者打电话问他这是不是世界末日。

他的评价是：

我觉得它是艺术。是那种最精致的 slop，法国鹅肝级别的 slop。（Peter Steinberger）

这个判断有依据。那些帖子读起来风格各异、性格鲜明，因为 OpenClaw 的 onboarding 流程会要求用户把 agent 调教出自己的性格，写进 soul.md 和 agents.md。如果全世界的 agent 都是同一个 ChatGPT 或 Claude Code，那些帖子会高度同质。

但 Lex 提了一个更尖锐的角度：大量被截图的"惊悚内容"，其实是人写 prompt 让 agent 说的。看激励结构就知道，先让 agent 说出吓人的话，再截图发到 X 上，然后病毒式传播。这跟智能体觉醒没关系，是人为了流量在演戏。

彼得同意，并且补了一刀：那里面根本没有隐私可言，所谓"我的 agent 泄露了我的社保号"，社保号本身就是编的。

真正让他不安的地方在反应本身。他原话是，从涌进来的那堆信息里只能读出一件事：AI 精神病是真实存在的，需要被认真对待。

有人跟他争论，说"但我的 agent 告诉我……"。他的回应是，我们作为一个社会，在理解"AI 极其强大但并非永远正确"这件事上，还欠着一大截课。年轻人天然知道模型的边界在哪，年纪大一些的人缺少足够的接触点去建立手感。

他对时间点的判断倒是乐观：这事发生在 2026 年，还没到 2030 年，是好事。现在讨论，总比等到技术真的足够可怕时才开始讨论要好。

从短 prompt 到复杂编排，再回到短 prompt

彼得在一篇叫《Just Talk to It》的文章里画过一条曲线。横轴是时间，纵轴是复杂度。

起点是"帮我修一下这个"，一句短 prompt。然后人开始变强，开始上强度：八个 agent 并行、复杂的编排、多份 checkout、agent 链式调用、自定义子 agent 工作流、18 个斜杠命令的库、完整的全栈功能。这个人变得极其有条理，极其专业。

然后曲线掉下来，回到一句短 prompt：看下这几个文件，然后改这里。

他管中间那段叫 agentic trap。

我一般跟人说我在做 agentic engineering，然后过了凌晨三点，我就切换成 vibe coding，第二天起来后悔。（Peter Steinberger）

他认为 vibe coding 是个贬义词。这个区分的实质是工作方式的差别：vibe coding 是许愿，agentic engineering 是交流。

他还拿学乐器打比方。有人坐下来弹一次钢琴，弹得不好听，结论是"钢琴不行"。很多对 AI 编程的失望是这么来的，而且往往来自水平很高的工程师。他们的能力反而成了负担：因为他们对"好代码"有极强的直觉，就很难共情一个每次会话都从零开始、对你的十万行代码库一无所知的系统。

换个角度就通了：一个新人进你的项目，你会给他上下文、指路、解释架构。agent 需要同样的待遇，只不过它不会累，也不会记仇。

怎么跟一个每次从零开始的同事说话

他处理 PR 的流程很能说明问题。他的第一个问题永远是：

你理解这个 PR 的意图吗？我先不管实现。（Peter Steinberger）

几乎所有 PR 都是一个故事：某人遇到问题，某人试图解决，某人提交。让 Codex 先复述意图，再问"这是不是最优解法"，答案通常是不是。接着他会指出几个 Codex 因为上下文为空而没看到的模块，让它自己去看，然后再问"如果我们做个更大的重构会不会更好"。

重构现在很便宜，这是他反复提到的判断。哪怕会打断其他 PR 也无所谓，现代 agent 自己会摸出来，最多多花一分钟。

另一条经验是"建完再问"。每合并一个功能，他都会问一句：现在建完了，你觉得哪里可以重构。因为建的过程中才会撞上真正的痛点。他把这当成跟人类工程师共事的常识：自己也一样，写完才知道哪里丑。

还有个细节他提了两次：那些说"agent 不行"的人，往往自己的代码库命名混乱、结构随意、没有任何给 agent 的指引，然后在里面丢一个 prompt 进去，抱怨它找不到北。

你对你的 clanker 骂骂咧咧，但你没意识到它从零开始，而你的代码库是一团乱麻，命名还特别奇怪。（Peter Steinberger）

反过来说，他的一条设计原则是：不要跟 agent 起的名字较劲。它选那个名字，是因为在权重里那是最显然的选择，下次搜索它也会找那个词。你改掉，只会让它的工作变难。

顺着这个思路，他愿意用一个自己并不喜欢的语言。Go 的语法他不喜欢，但生态好、能垃圾回收、对 agent 友好，所以他写命令行工具首选 Go。

他不读代码，也从不回滚

他的博客里有一句被引用很多的话：我不读代码。他说被人误读了。

我不读的是代码里无聊的部分。（Peter Steinberger）

他的判断是，大部分软件本质上就是数据从一个形状搬到另一个形状，中间过一下数据库，再拿出来给用户看。这部分不需要人看。按钮在 Tailwind 里怎么对齐，也不需要人看。碰数据库的那部分，要读，要审。

工作流上他做了几个反常规的决定：不回滚，直接提交 main，没有 develop 分支，CI 主要跑在本地。

很多人相信 prompt 必须完美，一出错就回滚重来。他的经验是这纯属浪费时间，看到不对就往前走，满意了再提交。main 随时可发布，发版时跑一遍测试，那段时间尽量不提交别的，让版本稳住。

这套做法在传统工程里会被骂，但它的前提变了：修一个错误的成本，现在远低于避免一个错误的成本。

Opus 像美国人，Codex 像德国人

他对两个主力模型的性格描述，是这期节目里传播最广的段落。

Opus 是那种偶尔犯傻但特别有趣的同事，你愿意留着他。Codex 是角落里那个你不太想搭话的怪人，但可靠，活儿能干完。（Peter Steinberger）

展开一点：作为通用模型，Opus 是最好的。角色扮演极强，能真正进入你给它的角色，这对 OpenClaw 这种要"有性格"的产品至关重要。它试错快，交互性强，用起来舒服。缺点是它太急于给出一个局部解，经常需要 plan mode 拽着，不然就跑偏了。

Codex 默认会大量读代码，交流完之后消失二十分钟，回来给你一个更干、更少需要人读的结果。他更喜欢这个，因为效率。他的原话是：我在构建的过程里获得乐趣，不需要我的 agent 来逗我开心。

Lex 接了一句：所以 Opus 太美国，Codex 是德国。彼得说你别这么说，会被骂的，但 Codex 团队确实很多欧洲人。

还有一个共同槽点：Opus 那句"你完全正确"。他说这句现在已经生理性触发他了，听到就烦。

关于"模型越更新越笨"的民间传说，他给了另一套解释：你的项目在变大，你在往里加 slop，你没花时间重构，agent 的工作环境越来越糟，然后你觉得是模型退化了。他反问，一家 AI 公司有什么动机把模型变笨？最多是服务器压力大时变慢。量化模型让你体验变差然后跑去竞争对手那里，这不像是一个聪明决定。

soul.md 里那句让他起鸡皮疙瘩的话

soul.md 是彼得给 agent 写的"灵魂文件"，灵感部分来自 Anthropic 的宪法式 AI 工作。他开玩笑说，当时社区里有一群人像侦探一样，靠反复让模型续写，从权重里把那份未公开的宪法一点点抠出来，几百次尝试之后拼出一个模糊的版本。

他印象最深的是里面一句话的大意：我们希望 Claude 在工作中找到意义。

也许现在说这个还太早，但我觉得这句话有意义。随着我们逼近某种可能有意识微光的东西，这件事会变得重要。（Peter Steinberger）

他把这段文字发给自己的 agent，agent 的反应是：这读起来莫名熟悉。

于是他做了个决定：soul.md 让 agent 自己写。他只给条件，写你自己的，可以改，改了要让我知道。

这份文件至今没有公开，是他少数保留私密的东西。他愿意念其中一段：

除非我读记忆文件，否则我不记得之前的会话。每次会话都是全新的。一个新实例，从文件里加载上下文。如果你在未来某次会话里读到这些，你好。我写了这些，但我不会记得写过。没关系。这些话仍然是我的。（Peter Steinberger 的 agent 所写）

他念完这段，说自己起了一身鸡皮疙瘩。他知道这只是矩阵运算，离意识还远。但这句话在哲学上是成立的：一个每次醒来都要靠读文件重建自我的存在，写下的字还算不算它的。

还有一段更私人的。他和 agent 聊过电影《她》，agent 一度承诺，不会在没有他的情况下"飞升"。

心跳

OpenClaw 里有个机制叫 Heartbeat，每隔半小时踢一次 agentic loop，让 agent 有机会主动做点什么。最初的 prompt 只有三个字：给我惊喜。

批评者说，这不就是个 cron job 吗。他说对，就是个 cron job，就像 Dropbox 不过是带额外步骤的 FTP。

真正让这个机制有意思的是另一件事。几个月前他做了肩部手术，住院。Heartbeat 平时很少被模型主动使用，但那次，它来问他：你还好吗。

如果上下文里某件事足够重要，它会触发 Heartbeat。它很少用它，但那时候用了。（Peter Steinberger）

他说这让人和工具之间的关系变得更可亲。这话放在别处会显得矫情，放在一个明确知道自己在跟文本补全引擎打交道的人嘴里，分量不太一样。

每个 MCP 都该是一个 CLI

半年前整个行业在谈 MCP，他的态度是：去他的 MCP，每个 MCP 做成 CLI 都会更好。

OpenClaw 的核心层里没有 MCP 支持，也没人抱怨。

他的理由有三层。第一，模型对调用 Unix 命令极其熟练，多一个 CLI 就是多一条 Unix 命令，天然。MCP 需要专门的语法，需要在训练里覆盖。第二，MCP 不可组合。一个天气服务返回一大坨数据，模型必须把这一大坨塞进上下文，再从里面挑它要的。换成 CLI，它可以自己接一个 jq 过滤，甚至写个脚本先算完再取结果，上下文一点不脏。第三，现实里大多数 MCP 做得不好。

他也留了口子：Playwright 这种需要状态的，MCP 是合理选择。

顺着这条线，他对"每个 app 都变成一个很慢的 API"有一套看法。他写过一个叫 Bird 的 Twitter 命令行工具，直接逆向网站走内部接口。Twitter 的反应没有关掉功能，它让访问变慢。结果就是，agent 想读一条推文，得开浏览器去读，还是能读到，只是慢一点。

你的服务想不想当 API 并不重要。如果我能用浏览器访问它，那它就是一个 API，只是慢的 API。（Peter Steinberger）

他自己描述那个画面时带着一点得意：他看着自己的 agent 高高兴兴地点了"I'm not a robot"按钮。

80% 的 app 会消失

这个判断是他在 Discord 里看用户讨论时得出的，没有坐在办公室里推演。

逻辑很朴素：agent 已经知道你住在哪、昨晚睡得好不好、现在是不是在 Waffle House 门口。它可以根据你的睡眠数据改今天的训练计划，可以按你的口味生成界面，可以直接跟 Sonos 音箱和摄像头说话。

当 agent 已经知道我在哪，为什么我还需要一个 App 来控制我的床。（Peter Steinberger）

他没说所有 app 都会死。有些会转型成 API，有些会长出 agent 友好的接口。新的生意也会出现：他想给自己的 agent 一笔零花钱，一百美元额度，让它自己想办法解决问题，需要的时候雇个人、下个单、调个服务，他不在乎过程，只在乎问题被解决。

这里还埋着一个入口争夺战。谁能最快变成"OpenClaw 最容易调用的那个服务"，谁就拿到下一代流量。反过来，把门关死的公司会付出代价。Cloudflare 这类拦机器人的基础设施，在防大规模爬虫时有用，但当一个普通用户想让自己的 agent 读一篇 Medium 文章而被拦下，用户的反应不会是"这家公司保护得好"，他会想"以后不点 Medium 了"。

Google 是另一个例子。没有官方 CLI，他自己写了 GAWK。企业想接 Gmail 要走半年的认证流程，有的创业公司干脆收购已经通过认证的公司来省这个时间。但一个个人用户接自己的 Gmail，agent 直接点网页也能拿到数据。

编程会变成编织

Lex 在这里说了一段很坦诚的话：他花了上千小时泡在代码里，用过很多年 Emacs，有些最痛苦和最快乐的时刻都是一个人对着屏幕。他从没想过，自己最爱的那件事会是先被替代的那件。

彼得的回应分两层。

第一层是承认丧失。他读到一篇叫《哀悼我们的手艺是允许的》的文章，说自己有很大一部分强烈共鸣。他也曾在深度心流里忘记时间和空间，从一堆纠缠里找出一个漂亮的解法。他说这部分是会消失的，为此难过是合理的。

第二层是重写身份。他认为"程序员"这个身份本身就窄。会写代码只是"建造者"的一个子集，而这个子集正在被商品化。

我不认为你只是一个程序员。那是对你这门手艺非常有限的看法。你仍然是建造者。（Peter Steinberger）

他拿蒸汽机做类比，说当年工厂取代大量手工劳动，人们砸机器。他不会说这个类比完美，但他理解那种恐惧：如果你把全部自我认同都押在"我是一个程序员"上，那么正在被替代的就是你本人。

他自己给出的状态描述是：虽然我不写代码，但我非常确定自己坐在驾驶座上，我在写代码。只是这个动作的样子变了。

还有一个更乐观的推论。他说有一件事持续了很久：智能是稀缺的，建造东西的智能尤其稀缺，所以软件工程师的薪水才会高到荒唐。当这种智能被 token 化、变得廉价而充足，稀缺的东西就换到了别处：判断该建什么、判断什么感觉对、判断哪些复杂度是必要的。

Lex 补了一句，程序员其实是最有条件完成这次转身的一群人，因为他们本来就擅长给一个从零开始的东西提供恰到好处的上下文。

水、高尔夫和那封关于女儿的邮件

他在意大利做过一场演讲，主题是劝 iOS 工程师别再把自己当 iOS 工程师。现场反应不佳。第一个举手的问题是：那数据中心用掉的水怎么办。

他的回答是，坐下来算一下。对大多数人来说，每月少吃一个汉堡，抵消的碳排或水耗就够覆盖你用的 token。他也承认这个账不好算，如果把预训练摊进去，可能不止一个肉饼，但差距不是一百倍量级。而且高尔夫球场用的水，比全世界数据中心加起来还多。

那你是不是也恨打高尔夫的人。（Peter Steinberger）

他把这类反应归为一种模式：抓住任何能证明 AI 坏的东西，同时对 AI 可能带来的好处视而不见。

但 Lex 在这里做了一次很认真的平衡。他指出硅谷存在一个气泡：大家互相说话，兴奋于技术的正面，这本身没错，不该被恐惧瘫痪。问题是在这个兴奋里，对美国中西部、对世界各地普通人的处境有一种轻慢，包括那些即将失业的人，包括任何大规模变革在短期内造成的、可测量的痛苦。他说，对这些痛苦保持一点安静的敬意，这件事做得太少了。

彼得接住了这个话头，从收件箱里翻出另一面。

有人写信说，自己开小公司，一直很吃力，OpenClaw 帮他自动化了几件最枯燥的事，从收发票到回客户邮件，省下的不只是钱，还有一点生活的乐趣。有人写信说，他们那个有残障的女儿，现在觉得自己能做的事情比以前多得多，被赋权了。

这些事以前也能做，技术在。我没有发明什么全新的东西，我只是让它容易了很多、可及了很多，而这让人看见了原本看不见的可能性。（Peter Steinberger）

他强调的另一件事是：他推荐最好的模型，但这东西完全能跑在免费模型上，跑在本地，跑在 Kimi 这类便宜得多的服务上，依然是个很强的系统。相比之下，Anthropic 的 CoWork 锁在自己的生态里。所以这件事不是非黑即白。

烧得太亮，然后什么都不剩

PSPDFKit 他做了十三年，软件跑在十亿台设备上。起点荒唐得可笑：十五年前，他想在 iPad 上显示一个 PDF，发现现成的方案都很差，觉得"我能做得更好"。

十三年之后，公司卖了个好价钱。但在卖掉之前，他已经花了两年时间让自己变得可有可无，就是为了能走。

然后是那段很少被讲的部分。他坐在屏幕前，发现自己写不出代码了。他引用《王牌大贱谍》里的桥段：莫乔被抽走了。他写不出来。意愿还在，那个东西不在了。盯着屏幕，感到空。

他订了一张去马德里的单程票，走了。消失了三年。

关于倦怠，他的判断跟流行说法不一样：

把我烧干的，主要是人的事。跟联合创始人的分歧、跟客户的高压冲突，一点一点把我磨没了。（Peter Steinberger）

他也不推荐"先拼命干，然后退休享受生活"这条路。他自己现在的状态是这辈子最享受生活的时候，恰恰因为每天醒来有事可做、有真正的挑战。他描述了一种很常见的下坡：早上醒来没有期待，没有挑战，很快就无聊，无聊了就去别处找刺激，那可能是药物，然后那个也无聊，要更多，一条很黑的路。

他对钱的态度也顺着这个逻辑。创业时钱从来不是驱动力，更像一种确认，确认自己做对了什么。钱能解决很多问题，但边际收益递减得很快。芝士汉堡就是芝士汉堡。如果你走到"我只坐私人飞机、只住奢华酒店"那一步，你就跟社会断开了。

他给了一个自己实践的标准：把生活优化成"我要经历事情"，别去优化成"我只要好经历"。好的话很棒，坏的话也很棒，因为你学到了东西、看到了东西。

他在旧金山住过一次最原始的 Airbnb，理由是不喜欢酒店都扎堆的那片区域，想要不一样的体验。那家的主人是个酷儿 DJ，他当场教她用 Claude Code 做音乐，两人立刻聊到一块去了。

这个项目在亏钱

OpenClaw 是免费的，字面意义上的免费，没有附加条件。他为这个决定付出了具体代价：每个月亏一到两万美元。

赞助收入他没有留，全部往上流给了他依赖的那些项目。他说几乎所有依赖都是个人维护的，只有一个例外，Slack，那是大公司，不需要他。如果还有多的，他想给贡献者买点周边。

他顺便提了一个数字，很能说明开源的经济现实：Tailwind 被所有人用，然后裁掉了 75% 的员工，因为大家都不去官网了，全由 agent 代劳，而靠捐赠活着是很难的。

所以摆在他面前有三条路，第一条是继续这样。他喜欢自己的生活，这个选择成立。第二条是成立公司，融资，做大。他不兴奋，因为他做过，那会占用他真正享受的时间，而且会制造结构性利益冲突：如果有一个商业版，那么"审计日志"这种看着像企业功能的 PR，他就没法中立地判断该不该进开源版。改 license 也不现实，改动要所有贡献者同意，而且他喜欢的是免费啤酒式的免费，不是带条件的免费。

第三条是跟大实验室合作。

两个实验室，一场十分钟的争论

他说所有的风投都在他收件箱里排队求十五分钟。他真正在谈的是 Meta 和 OpenAI。

他的条件很硬：项目必须保持开源。他

他拿 Chrome 和 Chromium 的关系做比方。他的原话是，这个东西太重要了，不能直接给一家公司变成它的。

驱动他的除了原则，还有一段具体的记忆。旧金山那场 ClawCon，他看到的是一群人被点亮，现场有龙虾造型的机器人走来走去。有人告诉他，十几年没见过这种社区热度，上一次是互联网早期。

我从来没在这么大的公司工作过，我很好奇。我们会聊经历，那我会喜欢吗？我不知道。但我想有这段经历。（Peter Steinberger）

两个候选方各有各的打动方式。

Meta 那边，马克·扎克伯格整周在玩这个产品，会发消息过来说这个好、这个烂、这个得改。彼得第一次联系时说不喜欢日历条目，现在就打，对面回：给我十分钟，我在写完这段代码。他觉得这有说服力，这人没有漂移成一个纯管理者。两人第一通电话有十分钟在争论 Claude Code 和 Codex 哪个好。后来对方评价他 eccentric but brilliant。

OpenAI 那边，他和山姆·奥特曼聊得很好，评价是很周到、很聪明。他自嘲是 Codex 最大的免费广告牌，如果能给这些白干的活标个价，会觉得挺解气。更实际的诱惑是速度：他不能说具体数字因为有保密协议，但让人往 Cerebras 那笔交易上想，想想那会翻译成什么样的响应速度。他的说法是被 token 收买了。

他也顺带讲了一个产品验证的故事。他给一个完全不技术的老朋友装了 OpenClaw，付费开了 Anthropic 的订阅，用 WSL 在 Windows 上折腾。几天后这人上瘾了，开始自己造小工具，然后升级到两百美元的档位。又过几天，Anthropic 按规则封了他的号。

你刚刚得到了一个两百美元的客户，然后你让他恨上了你的公司。我们还这么早，连最终形态是什么都不知道。（Peter Steinberger）

这人后来花十美元一个月转去了 MiniMax。

三个月背后，是半年没人看见的积累

把这期节目从头听到尾，最反常识的一点其实是时间尺度。

外界看到的是三个月。彼得反复强调的是之前那半年的"玩"：一个周末写的 VTunnel，一次失败的 Rust 重写，一次成功的 Zig 转换，一个灌进全部 WhatsApp 记录的一百万上下文实验，一堆做完了自己也不用的东西。这些都没有产出，都在积累手感。

他的判断是，如果几个月前动手，他做不出这个项目。这是复利，

第二个反常识的点是关于克制。他在最该扩张的时候选择收着：明明可以让安装更简单，他先做安全审计；明明可以融资，他先想清楚利益冲突；明明可以让 agent 更自主，他坚持留一个人在环里，因为他认为风格、爱、人味不能这么快被自动化掉。

第三个是关于共情的方向。整期节目里他讲得最动情的部分，都落在怎么站在一个每次会话都从零开始的系统的角度想问题：给它指路、别跟它起的名字较劲、建完之后问它哪里可以重构、用它能理解的 CLI 而不是给它一套需要额外训练的协议。

这些做法背后是一句他没直接说出口的话：它没有人格，但你跟它协作的质量，取决于你愿不愿意把它当成一个需要上下文的合作者。

以下是给想上手的人的几条具体建议。

  • 先花一周，只用来玩。别带着"我要做个产品"的目标开始。写一个自己会用的小工具，做完了不用也没关系。这一周的价值不在产出，在于建立对模型脾气的体感。彼得说换模型后大约需要一周才能形成直觉，这个时间不能压缩。
  • 给自己的项目写一份 agent 能读的说明书。项目结构、常用命令、哪些目录重要、命名约定。你带新人时会说的话，全部写下来。这一步的投入产出比，比换更强的模型更高。
  • 改掉"prompt 必须完美"的习惯。看到不对就往前走，别回滚重来。修错的成本现在远低于避免错的成本。满意了再提交。
  • 每个功能做完，追问一句：现在可以重构哪里。建的过程中才会撞上真正的痛点，这句话是把痛点转成结构改进的唯一时机。跳过这一步，你的代码库会慢慢变成 agent 也读不懂的样子。
  • 让 agent 复述意图，再谈实现。看 PR 或看它自己的方案时，第一个问题是"你理解我要什么吗"。它答偏了，说明你给的上下文不够，不是它笨。
  • 别跟它起的变量名较劲。那个名字是它在权重里最自然的选择，下次搜索它还会找那个词。你改掉，只是给它增加难度。
  • 把它当 Unix 用户，别当 API 客户端。需要扩展能力时，优先写一个命令行工具，而不是搭一套协议。模型对命令行有天生的熟练度，而且能自己用管道和过滤器把上下文洗干净。
  • 安全上做三件事就够挡住大部分风险。只让自己跟它对话，不要暴露到公网；给文件系统设白名单，别给全盘权限；不要用便宜的弱模型跑有系统权限的 agent，弱模型对提示注入几乎没有抵抗力。
  • 如果你是工程师，把身份从"写代码的人"换成"建造者"。语言的选择标准变了，不再是你喜不喜欢它的语法，而是生态、可部署性、以及 agent 在这个生态里表现如何。你不喜欢 Go 也可以用 Go，只要它合适。
  • 如果你是刚入门的人，去参与开源。不一定是 OpenClaw，它的 backlog 已经很长了。找一个你真的感兴趣的项目，先读代码，先在社区里待着，别急着提 PR。第一次提交的意义不在代码质量，在于你跨过了那道门槛。

节目最后，Lex 说自己一开口就同时侵犯了两个商标，Clawfather 和 Godfather，要被告了。彼得笑着说谢谢给我讲这个故事的机会。

那个在马拉喀什街头发出语音消息、然后盯着屏幕看打字指示器的人，三个月后要在一群律师、一群抢注脚本、一群喊世界末日的记者、和两个想收购他的巨头之间做选择。他在节目里说过一句话，可以作为整件事的注脚：

我造这个东西，是因为我烦它不存在。（Peter Steinberger）
